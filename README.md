# Game Server

Асинхронный многопоточный HTTP-сервер для онлайн-игры, реализованный на C++17. Сервер обрабатывает игровые сессии, управляет состоянием игроков, генерирует предметы на карте, детектирует столкновения и ведёт таблицу лидеров в PostgreSQL.

## Стек

- **Язык:** C++17
- **Сеть:** Boost.Asio, Boost.Beast
- **Сериализация:** Boost.Serialization, Boost.JSON
- **Логирование:** Boost.Log (JSON-формат)
- **База данных:** PostgreSQL, libpqxx
- **Сборка:** CMake, Conan 1.64
- **Деплой:** Docker (multi-stage build), docker-compose
- **Тестирование:** Google Test

## Возможности

- REST API с 7 эндпоинтами для управления игровыми сессиями
- Асинхронная обработка запросов на пуле потоков с использованием `boost::asio::strand` для потокобезопасности
- Система детекции столкновений на основе математических проекций точек на отрезки (без тяжёлых операций `sqrt`)
- Пространственный индекс дорог для быстрого поиска через `std::map<Coord, std::vector<const Road*>>`
- Вероятностный генератор трофеев с балансируемой периодичностью появления
- Пул соединений с PostgreSQL, параметризованные запросы и индексы для быстрого ранжирования лидерборда
- Отказоустойчивое сохранение состояния сессии через атомарную запись (write-to-tmp, rename)
- Автоматическое удаление неактивных игроков (dog retirement) по сигналу через Boost.Signals2
- Поддержка ручного и автоматического режимов продвижения игрового времени (tick)

## Архитектурные решения

### Потокобезопасность
Каждая игровая сессия защищена `strand`, что исключает гонки данных при параллельной обработке запросов от разных клиентов на одном пуле потоков.

### Обработка столкновений
Вместо полного перебора дорог при каждом тике используется пространственный индекс: дороги разделяются на горизонтальные и вертикальные, индексация по координате. Это снижает сложность поиска с O(N) до O(log N + K).

### Сохранение состояния
Состояние игры сериализуется через Boost.Serialization во временный файл, после чего выполняется атомарная операция `rename`. Это гарантирует, что при сбое питания или краше процесса файл состояния не окажется повреждённым.

### Работа с БД
Класс `GameRepository` автоматически создаёт таблицы при первом подключении через `CREATE TABLE IF NOT EXISTS`, что избавляет от необходимости ручной инициализации схемы.

## Как запустить

### Способ 1. Docker Compose (рекомендуется)

Поднимает сервер и PostgreSQL одной командой:

```bash
docker compose up --build

Сервер будет доступен на http://localhost:8080.
Остановка: docker compose down
Остановка с удалением данных БД: docker compose down -v
Способ 2. Сборка из исходников
mkdir build && cd build
conan install .. --build=missing -s compiler.libcxx=libstdc++11 -s build_type=Release
cmake -DCMAKE_BUILD_TYPE=Release ..
cmake --build . --config Release -j$(nproc)
cd ..
export GAME_DB_URL="postgres://user:password@localhost:5432/game_db"
./build/game_server -c data/config.json -w static
Сервер будет доступен на http://localhost:8080.

Доступные флаги:
-c, --config-file <path> — путь к конфигу карты
-w, --www-root <path> — путь к статическим файлам
--tick-period <ms> — включить автоматический режим тиков с указанным периодом
--randomize-spawn-points — случайное размещение новых игроков на карте
--state-file <path> — путь к файлу сохранения состояния
--save-period <ms> — период автосохранения
